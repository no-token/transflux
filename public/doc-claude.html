SETUP沉浸式翻译配置方法

  1. 沉浸式翻译「设置」→「翻译服务」→「添加自定义翻译服务」，选择 Claude；
  2. API URL 填：https://your-gateway.example.com/v1/messages；
  3. API Key 填网关对外 AUTH_KEY；「模型」随意（如 gateway，网关忽略该字段）；
  4. 「每秒最大请求数」先设 1~2，稳定后再按上游能力调高；点「测试服务」通过后启用。

目标语言识别：网关从请求的提示词（system + user）中自动识别目标语言（如 "Translate ... into Chinese (Simplified)" / "翻译成日语"）。如需强制指定，可在 URL 追加 ?to=zh（配合 ?token= 或 x-api-key 均可）。未识别到时默认翻译为中文。

POST/v1/messages — Anthropic Messages 兼容

POST {base}/v1/messages

别名 /anthropic/v1/messages 等价。网关取最后一条 user 消息中的原文（兼容 <text> 包裹、"## Original Text" 区段等常见提示词格式）送网关上游翻译，以 Anthropic message 结构返回。支持 stream: true（SSE）。

字段必填说明
messages必填Anthropic 消息数组（content 为字符串或 [{type:"text",text:"..."}] 均可）；原文取自最后一条 user 消息，≤ 10000 字符
system可选仅用于目标语言识别，不参与路由
model可选仅回显，不参与路由（实际由网关上游池翻译）
stream可选true 时以 SSE 返回 message_start → content_block_delta → message_stop 事件序列
 
# curl 示例
curl -X POST "https://your-gateway.example.com/v1/messages?to=zh" \
  -H "x-api-key: YOUR_GATEWAY_KEY" \
  -H "anthropic-version: 2023-06-01" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "gateway",
    "max_tokens": 2048,
    "messages": [
      { "role": "user", "content": "Translate into Chinese: Hello, world!" }
    ]
  }'
// 成功响应（200）— 与 Anthropic Messages 结构一致
{
  "id": "msg_xxxxxxxxxxxx",
  "type": "message",
  "role": "assistant",
  "model": "gateway",
  "content": [
    { "type": "text", "text": "你好，世界！" }
  ],
  "stop_reason": "end_turn",
  "stop_sequence": null,
  "usage": { "input_tokens": 21, "output_tokens": 2 }
}

说明：usage 为估算值；模型名回显请求中的 model；anthropic-version 头无需关心（任意值均可）。实际翻译由网关按优先级 + 剩余额度在多家上游中自动路由，无需任何大模型 API Key。
