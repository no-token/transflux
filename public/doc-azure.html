Transflux · Azure 渠道接口文档Azure Translator 兼容

入参与响应同微软 Azure Translator v3.0，已有 Azure SDK / 代码可直接换 Base URL 接入
本服务 Base URL：https://your-gateway.example.com（即当前页面的访问地址）
鉴权密钥：由网关管理员发放（网关对外 AUTH_KEY），与 Azure Subscription Key 用法一致。

AUTH鉴权

请求头携带 Ocp-Apim-Subscription-Key（推荐，与 Azure 完全一致）。也兼容 Authorization: Bearer <key>。

# 头部示例
Ocp-Apim-Subscription-Key: YOUR_GATEWAY_KEY

POST/azure/translate — 文本翻译

POST {base}/azure/translate?api-version=3.0&to=<lang>[&from=<lang>]

等价别名：POST {base}/translate（参数完全一致）。多目标语言可重复 to，最多 10 个。

Query 参数必填说明
api-version必填固定 3.0
to必填目标语言，可重复传最多 10 个；每个目标语言各计一次字符
from可选源语言，缺省自动检测
textType可选plain（默认）或 html。传 html 时标签原样保留，仅翻译文本（服务于沉浸式翻译等网页翻译客户端）
provider可选网关扩展：强制指定上游（baidu / alibaba / volcengine / azure / deepl）
Body说明
[{ "Text": "..." }]JSON 数组，1–100 条，每条为非空字符串
 
# curl 示例
curl -X POST "https://your-gateway.example.com/azure/translate?api-version=3.0&to=zh-Hans" \
  -H "Ocp-Apim-Subscription-Key: YOUR_GATEWAY_KEY" \
  -H "Content-Type: application/json" \
  -d '[{ "Text": "Hello, world!" }]'
// Node.js（一次请求译出中 + 日）
const resp = await fetch("https://your-gateway.example.com/azure/translate?api-version=3.0&to=zh-Hans&to=ja", {
  method: "POST",
  headers: { "Ocp-Apim-Subscription-Key": "YOUR_GATEWAY_KEY", "Content-Type": "application/json" },
  body: JSON.stringify([{ Text: "Hello, world!" }]),
});
const data = await resp.json();
// 成功响应（200）— 数组顺序与请求一一对应
[
  {
    "detectedLanguage": { "language": "en" },
    "translations": [
      { "text": "你好，世界！", "to": "zh-Hans" },
      { "text": "こんにちは、世界！", "to": "ja" }
    ]
  }
]

路由说明：多上游由网关按优先级 + 剩余额度自动路由，额度到阈值自动切换下一家；也可用 ?provider= 强制指定。

GET/usage — 当月用量

GET {base}/usage

同一网关密钥鉴权，返回当月各上游消耗与剩余额度。

curl "https://your-gateway.example.com/usage" -H "Ocp-Apim-Subscription-Key: YOUR_GATEWAY_KEY"

错误格式

统一 Azure 风格：{ "error": { "code": <数字码>, "message": "..." } }

HTTPcode含义
400400000参数错误（缺 api-version / to、body 非法等）
401401000网关密钥缺失或不正确
503503000无可用上游（全部被禁用 / 未配置 / 上游超时）
500500000网关内部错误

限制

单请求文本条数≤ 100 条
目标语言数（to）≤ 10 个
上游超时8 秒
计费口径源文本字符数 × 目标语言数

方言码自动映射：同一语言的多种写法（如 zh / zh-Hans、ja / jp）均可使用，网关自动转换为路由到的上游厂商的代码规范——简体中文→Azure zh-Hans / DeepL ZH / 百度 zh；繁体中文→Azure zh-Hant / DeepL ZH-TW / 百度 cht；文言文→Azure lzh / 百度 wyw。业务侧统一使用上表即可，无需关心各厂商差异。注意：DeepL 上游不支持粤语（yue）与文言文（wyw）。
