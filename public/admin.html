POST/translate — 文本翻译

入参与 Azure Translator v3.0 一致，已有 Azure SDK / 代码可直接换 base URL 接入。

POST /translate?api-version=3.0&to=<lang>[&to=<lang2>][&from=<lang>]

等价别名：POST /azure/translate（带渠道前缀，入参/鉴权完全一致，便于按渠道对外分发）。

Query 参数必填说明
api-version必填固定 3.0，其他值返回 400
to必填目标语言，可重复传最多 10 个；每个目标语言计费一次（字符 × 目标数）
from可选源语言，缺省自动检测（auto）
textType可选plain（默认）或 html；传 html 时标签原样保留仅翻译文本（适配沉浸式翻译等网页翻译客户端）
provider可选网关扩展：强制指定服务商（baidu / alibaba / volcengine / azure / deepl），跳过优先级路由
Body说明
[{ "Text": "..." }]JSON 数组，1–100 条；Text 或小写 text 均可，每条非空字符串
curl -X POST "http:///translate?api-version=3.0&to=zh-Hans" \ -H "Ocp-Apim-Subscription-Key: YOUR_GATEWAY_KEY" \ -H "Content-Type: application/json" \ -d '[{ "Text": "Hello, world!" }]'
// Node.js（多目标语言：一次请求译出中 + 日） const resp = await fetch("http:///translate?api-version=3.0&to=zh-Hans&to=ja", { method: "POST", headers: { "Ocp-Apim-Subscription-Key": "YOUR_GATEWAY_KEY", "Content-Type": "application/json" }, body: JSON.stringify([{ Text: "Hello, world!" }]), }); const data = await resp.json();
// 成功响应（200）— Azure 风格数组，顺序与请求一一对应 [ { "detectedLanguage": { "language": "en" }, "translations": [ { "text": "你好，世界！", "to": "zh-Hans" }, { "text": "こんにちは、世界！", "to": "ja" } ] } ]

多语言场景由网关按优先级 + 剩余额度自动路由：优先级小者先用，额度到阈值自动切下一家；也可用 ?provider= 强制指定。

强制路由的取值是「接入名」：内置五家用 baidu / alibaba / volcengine / azure / deepl，多 Key 实例用实例名（如 baidu-2，在服务商页创建）。

GET/usage — 当月用量

查询当月各服务商消耗与剩余额度（同一网关密钥鉴权）。

curl "http:///usage" -H "Ocp-Apim-Subscription-Key: YOUR_GATEWAY_KEY" // 响应（200） { "month": "2026-11", "totalUsed": 123456, "providers": [ { "name": "baidu", "configured": true, "enabled": true, "autoDisabled": false, "priority": 20, "quota": 500000, "monthUsed": 45678, "remaining": 454322, "pct": 9 } ] }

POST/azure/translate — Azure Translator 兼容翻译

与 /translate 完全等价的带渠道前缀入口；鉴权同 Azure：Ocp-Apim-Subscription-Key 头。

POST /azure/translate?api-version=3.0&to=<lang>[&from=<lang>]
要点说明
鉴权Ocp-Apim-Subscription-Key: <网关密钥>（兼容 Authorization: Bearer）
Body[{ "Text": "..." }]，1–100 条
多目标to 可重复最多 10 个，每目标各计一次字符

POST/baidu/api/trans/vip/translate — 百度通用翻译兼容

支持 form 表单（推荐）、JSON 与 GET query。签名规则与百度官方一致：sign = MD5(appid + q + salt + 密钥) 取 32 位小写；appid 任意非空字符串，密钥填网关对外 AUTH_KEY。

POST /baidu/api/trans/vip/translate
参数必填说明
q必填翻译文本（UTF-8，≤6000 字符）；\n 分隔多行，逐行返回
from可选源语言，auto 或留空自动检测
to必填目标语言（百度代码：zh / jp / kor / fra / cht …）
appid必填任意非空字符串（如 gateway）
salt / sign必填随机数与 MD5 签名
curl -X POST "http:///baidu/api/trans/vip/translate" \ --data-urlencode "q=Hello, world!" \ -d "from=en&to=zh&appid=gateway&salt=1435660288" \ -d "sign=$(echo -n "gatewayHello, world!1435660288YOUR_GATEWAY_KEY" | md5sum | cut -d' ' -f1)" // 200 成功响应（百度结构） { "from": "en", "to": "zh", "trans_result": [ { "src": "Hello, world!", "dst": "你好，世界！" } ] } // 错误（同为 HTTP 200）：{ "error_code": "54001", "error_msg": "签名错误…" } // 52002 上游不可用 · 54000 缺参 · 54001 签名错 · 58003 q 超长

实际翻译仍由网关按优先级 + 额度自动路由多家上游，对接方无需百度账号。

POST/imme — 沉浸式翻译自定义 API

协议与沉浸式翻译官方文档（服务 → 自定义接口翻译）一致；鉴权 ?token=网关密钥 或 Bearer 头。

POST /imme?token=YOUR_GATEWAY_KEY
要点说明
请求体{ "source_lang": "auto", "target_lang": "zh", "text_list": ["...", ...] }，≤100 条 / 50000 字符
响应{ "translations": [{ "detected_source_lang": "en", "text": "…" }] }，与 text_list 等长同序
沉浸式翻译开发者设置开启 Beta → 「自定义 API」服务的 API URL 填 https://域名/imme?token=密钥

POST/v1/chat/completions — OpenAI 兼容翻译

取最后一条 user 消息中的原文（兼容 <text> 包裹等常见提示词格式）送网关上游翻译，以 assistant 消息返回译文；支持 stream（SSE）。鉴权 Authorization: Bearer 网关密钥。

POST /v1/chat/completions[?to=zh]
要点说明
目标语言URL ?to= 强制指定 > 从提示词自动识别（如 "into Chinese"）> 默认 zh
响应标准 chat.completion 结构（usage 为估算值；model 回显请求值）
沉浸式翻译添加自定义 AI 服务：API URL 填 https://域名/v1/chat/completions，API Key 填网关密钥，模型随意
兼容方式别名 /openai/v1/chat/completions 等价；部分客户端只需填 Base URL + 密钥

路由模式
多渠道可用时如何分派请求。优先级：固定顺序、失败降级，译风最统一；均衡消耗：按「已用 / 额度」比例路由，各池匀速用完，无随机。切换即时生效。
自动禁用阈值
当月用量达到免费额度的该比例时，自动停用该路由（松开滑块即保存）。

网关对外密钥

翻译缓存
