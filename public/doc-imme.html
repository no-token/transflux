按沉浸式翻译官方「自定义接口翻译」协议实现，批量文本 + 占位符透传
本服务 Base URL：https://your-gateway.example.com（即当前页面的访问地址）
鉴权：URL 追加 ?token=<网关对外 AUTH_KEY>，或请求头 Authorization: Bearer <网关密钥>

SETUP沉浸式翻译配置方法

  1. 打开沉浸式翻译「设置」→「开发者设置」，勾选开启 「启用 Beta 测试特性」。
    「自定义 API」是 Beta 隐藏服务：未开启 Beta 前，「添加自定义翻译服务」弹窗里看不到它，这是官方设计而非缺失。
  2. 回到「翻译服务」→「添加自定义翻译服务」→ 列表中此时会出现 「自定义 API」；选中后在「API URL」填入：
    https://your-gateway.example.com/imme?token=你的网关密钥
  3. 建议将「每秒最大请求数」先设为 1~2，稳定后再按网关上游能力调高；「每次请求最大段落数」可设为 3~25；
  4. 点击「测试服务」，通过后把网页翻译服务切换为该自定义 API。

POST/imme — 批量文本翻译

POST {base}/imme

Content-Type: application/json。协议与沉浸式翻译官方「自定义接口翻译」文档一致。

字段必填说明
text_list必填待翻译文本字符串数组，≤ 100 条，总长 ≤ 50000 字符
target_lang必填目标语言代码（如 zh / en / zh-TW）
source_lang可选源语言代码，auto 或省略为自动检测
 
# curl 示例
curl -X POST "https://your-gateway.example.com/imme?token=YOUR_GATEWAY_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "source_lang": "auto",
    "target_lang": "zh",
    "text_list": ["Hello, world!", "Good morning."]
  }'
// 成功响应（200）— translations 与 text_list 等长同序
{
  "translations": [
    { "detected_source_lang": "en", "text": "你好，世界！" },
    { "detected_source_lang": "en", "text": "早上好。" }
  ]
}

占位符说明：沉浸式翻译会把网页中的表情、公式等非文本内容替换为 {0} {1} 形式的占位符后随文本传入，网关原样透传给上游并在响应中带回，由客户端还原。若某上游习惯性改写花括号内容导致还原失败，可在后台调整服务商优先级避开该上游。

方言码自动映射：同一语言的多种写法（如 zh / zh-Hans、ja / jp）均可使用，网关自动转换为上游厂商的代码规范——简体中文→Azure zh-Hans / DeepL ZH / 百度 zh；繁体中文→Azure zh-Hant / DeepL ZH-TW / 百度 cht；文言文→Azure lzh / 百度 wyw。业务侧统一使用上表即可，无需关心各厂商差异。注意：DeepL 上游不支持粤语（yue）与文言文（wyw），目标语言为这两者且路由到 DeepL 时会返回上游错误。
